Good — here are concise, practical deployment options and recommended steps so colleagues on the intranet can reach the frontend.

Recommended approach (serve SPA from backend/wwwroot)
1. Use the all-in-one deployment script from the repo root:
   - PowerShell -ExecutionPolicy Bypass -File .\scripts\deploy-all.ps1
   - This deploys backend first, then frontend. The backend step publishes a self-contained ASP.NET Core build, backs up existing workhour.db* files, cleans the publish folder, writes start-backend.ps1, and copies backend support files. The frontend step deploys dist/ into backend/wwwroot; if dist/ is missing, it runs npm run build automatically.
2. Or run the same deployment in two explicit steps:
   - Backend first:
     PowerShell -ExecutionPolicy Bypass -File .\backend\Scripts\deploy-backend-selfcontained.ps1 -PublishDir 'E:\MISCMFactoryService\backend' -Configuration Release -Runtime win-x64 -AspDotNetCorePort 5080
   - Frontend second:
     PowerShell -ExecutionPolicy Bypass -File .\frontend\deploy-frontend.ps1 -Destination 'E:\MISCMFactoryService\backend\wwwroot'
3. Useful parameters
   - deploy-all.ps1 -BackendPublishDir 'D:\Apps\WorkHour\backend': customize backend publish/deploy path.
   - deploy-all.ps1 -FrontendDestination 'D:\Apps\WorkHour\backend\wwwroot': customize where frontend files are copied.
   - deploy-all.ps1 -BackendPort 5080: set the port written into generated start-backend.ps1.
   - deploy-all.ps1 -DbBackupRoot 'E:\WorkhourDBBackups': customize backup location for existing DB files.
   - deploy-all.ps1 -Mirror: mirror frontend dist/ to wwwroot, removing stale files.
   - deploy-all.ps1 -FrontendSource 'E:\GitHub\WorkHourTool\frontend\dist': deploy a specific prebuilt frontend folder.
4. Ensure backend serves static files
   - Program.cs already serves default/static files and rewrites non-API SPA routes to index.html.
   - If hosting frontend separately through IIS/nginx, configure equivalent history-mode fallback.
5. Start or restart backend
   - Run the generated start-backend.ps1 in the publish folder, or use your Scheduled Task/Windows Service registration.
6. DNS, firewall, and access
   - Create an intranet DNS name (e.g. factory-ui.company.local) pointing to the server.
   - Open the server port in firewall (HTTP/HTTPS). Prefer HTTPS.
7. Configure HTTPS
   - Use IIS or reverse proxy to terminate TLS, or configure Kestrel with a cert. Prefer internal cert from AD CA.
8. CORS / same-origin
   - If SPA is served from same host+port as backend, CORS not needed.
   - If you host separately, allow the SPA origin in backend CORS policy.
9. SPA routing rewrite (important)
   - If your router uses history mode, configure fallback so unknown paths return index.html:
     - IIS: add URL Rewrite rule (or use web.config produced by Vite).
     - nginx: try_files $uri /index.html;
     - Kestrel: middleware to rewrite to index.html for non-API requests.
10. Health & logging
   - Ensure static files are accessible; enable Serilog logs (already configured).
   - Add a small health endpoint on backend and a lightweight status page.
11. Security & production hygiene
   - Remove dev-only settings, disable file listing, set caching headers for static assets, enable CSP, enable HTTPS, run under least privilege service account, limit who can access DB files.

Minimal checklist to run now
- From repo root, run: PowerShell -ExecutionPolicy Bypass -File .\scripts\deploy-all.ps1
- For custom install path, pass -BackendPublishDir and -FrontendDestination.
- Start or restart the backend via generated start-backend.ps1, Scheduled Task, or Windows Service.
- Add intranet DNS + firewall rule for HTTP(S)
